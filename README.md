# INGOSight (MAIL-AGENT)

Локальный помощник по почте: саммари переписки, черновик ответа и утренняя сводка. Почта забирается по IMAP, модель работает через Ollama, данные лежат в SQLite и ChromaDB. Письма сами не отправляются.

## Запуск

На сервере, в каталоге проекта:

```bash
cp .env.example .env
docker compose up --build -d
```

Интерфейс: `http://GPUnStorageServer.local:18080` (порт задаётся `APP_PORT` в `.env`).

Первый старт скачивает образы и модели `qwen2.5:7b-instruct` и `nomic-embed-text`. Пока модели качаются, экраны почты уже открываются; генерация ответит ошибкой, пока Ollama не готова.

На стенде GPU — RTX 3060 12 ГБ, и его может занимать другой контейнер Ollama. Свой сервис проекта всё равно стартует с GPU; если памяти не хватает, запрос повторяется на CPU. Это медленнее, но данные почты не теряются.

Проверка без браузера: `python -m unittest discover -s backend/tests -t backend` из корня репозитория. Сквозные сценарии: `npm test` в каталоге `e2e` (нужен запущенный стенд).

## Gmail

OAuth не используется. В поле пароля — пароль приложения Google (16 букв, пробелы можно не убирать):

1. В Gmail включите IMAP.
2. Аккаунт Google → Безопасность → Пароли приложений.
3. Вставьте пароль в «Пароль» на экране настроек или в `IMAP_PASSWORD`.
4. Режим переключите на IMAP и нажмите «Проверить подключение», затем «Синхронизировать».

Для разработки и автотестов оставьте `IMAP_MODE=mock`: письма берутся из `fixtures/emails`.

## Удаление данных

```bash
docker compose down -v
```

Тома SQLite, ChromaDB и моделей Ollama удаляются. Чужие контейнеры на сервере эта команда не трогает.
