# Инструкция INGOSight (MAIL-AGENT)

Локальный помощник по почте. Письма забираются по IMAP только на чтение, модель работает на вашем сервере через Ollama, письма и индекс лежат в SQLite и ChromaDB. Приложение **не отправляет** почту: черновик копируется в буфер обмена, отправку делает человек в своём почтовом клиенте.

Один ящик, один пользователь, без OAuth и без облачных языковых моделей.

Краткая шпаргалка по запуску — в [README.md](README.md).

## Минимальные технические требования

| | |
| --- | --- |
| ОС | Linux x86_64 |
| Контейнеры | Docker Engine и Docker Compose V2 (`docker compose`) |
| GPU | NVIDIA, ориентир от 24 ГБ видеопамяти под `qwen2.5:7b-instruct` |
| Драйвер | Драйвер NVIDIA и [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html). В `docker-compose.yml` у сервиса Ollama указано `gpus: all` |
| Диск | Свободное место под образы и том моделей. `qwen2.5:7b-instruct` и `nomic-embed-text` вместе занимают порядка 5 ГБ, плюс образы контейнеров |
| Сеть | Исходящий доступ к IMAP-серверу (обычно порт 993). При первой сборке — доступ к реестру образов и к загрузке моделей Ollama |
| Порты на хосте | `APP_PORT` (по умолчанию **18080**) — веб-интерфейс. **11434** — HTTP API Ollama |
| Браузер | Актуальные Chrome, Edge или Safari |

Без GPU сервис Ollama из этого compose-файла не стартует: контейнер запрашивает все видеокарты. Если видеопамяти не хватает уже во время генерации, приложение повторяет запрос на CPU; ответ будет заметно медленнее.

Веб-интерфейс отдаёт только фронтенд. Backend и ChromaDB наружу не публикуются.

## Развёртывание на Linux

Нужен пользователь, которому разрешён запуск Docker. Системные пакеты и NVIDIA Container Toolkit ставятся один раз, до запуска проекта.

### 1. Проверить Docker и GPU

```bash
docker compose version
nvidia-smi
```

`nvidia-smi` должен показать видеокарту. Если команда `docker compose` не найдена, установите плагин Compose V2 вместе с Docker Engine.

### 2. Получить код

```bash
git clone <url-репозитория> INGOSight
cd INGOSight
```

Дальше все команды выполняются из каталога проекта.

### 3. Создать `.env`

```bash
cp .env.example .env
```

Откройте `.env` и смените `SECRET_KEY`. Значение `change-me` годится только для проверки на стенде. От этого ключа шифруется пароль IMAP, сохранённый в интерфейсе. Если ключ сменить после сохранения пароля, расшифровать его уже не получится: пароль придётся ввести заново.

`APP_PORT` можно оставить `18080` или задать свободный порт.

Почту можно прописать здесь (`IMAP_HOST`, `IMAP_PORT`, `IMAP_SSL`, `IMAP_USER`, `IMAP_PASSWORD`, `IMAP_MODE=imap`) или позже на экране «Настройки». Для первой проверки без живого ящика оставьте `IMAP_MODE=mock`: письма берутся из `fixtures/emails`.

Остальные переменные:

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `OLLAMA_URL` | `http://ollama:11434` | Адрес Ollama внутри сети compose. Менять не нужно |
| `MODEL_NAME` | `qwen2.5:7b-instruct` | Модель ответов. Её же скачивает контейнер Ollama |
| `EMBED_MODEL` | `nomic-embed-text` | Модель эмбеддингов для поиска по треду |
| `SYNC_DAYS` | `30` | Сколько дней входящих забирать. В интерфейсе допустимо 1–365 |
| `DIGEST_HOURS` | `24` | Окно утренней сводки в часах. В интерфейсе допустимо 1–168 |
| `DIGEST_HOUR` | `8` | Час автоматической сводки (минута 00). В интерфейсе этого поля нет |

`DIGEST_HOUR` считается по часам контейнера. В образе часовой пояс по умолчанию UTC.

`OLLAMA_URL`, `CHROMA_HOST` и путь к базе compose задаёт сам. Значения из `.env` для них внутри контейнера backend не используются.

### 4. Запустить

```bash
docker compose up --build -d
```

Первый запуск собирает backend и frontend, скачивает образы и модели `qwen2.5:7b-instruct` и `nomic-embed-text`. Пока модели качаются, страницы уже открываются, но саммари, вопрос, черновик и сводка ответят ошибкой.

### 5. Дождаться готовности

```bash
docker compose ps
docker compose logs -f ollama
```

В логах Ollama должны пройти оба `ollama pull`. Выход из просмотра логов: Ctrl+C (контейнеры при этом не останавливаются).

Проверка с сервера:

```bash
curl -fsS "http://127.0.0.1:${APP_PORT:-18080}/" -o /dev/null
curl -fsS http://127.0.0.1:11434/api/tags
```

Интерфейс: `http://<адрес-сервера>:18080` (или ваш `APP_PORT`). Если браузер на другой машине, этот порт должен быть доступен в сети.

На экране «Настройки» у модели зелёная точка означает, что Ollama отвечает.

### 6. Подключить почту и забрать письма

1. Откройте «Настройки».
2. Режим — «IMAP (Gmail и другие)». Для пробного ящика оставьте «Тестовый ящик».
3. Заполните сервер, порт, SSL, логин и пароль. Таблица серверов — в разделе ниже.
4. Нажмите «Сохранить», затем «Проверить подключение», затем «Синхронизировать».

Синхронизация ручная: кнопка есть и в списке тредов, и в настройках. Пока она идёт, интерфейс опрашивает статус (до нескольких минут на большом ящике). Письма сами по расписанию не подтягиваются.

Смена ящика (другой сервер или логин) удаляет уже загруженные письма, треды и векторный индекс. Настройки и новый пароль сохраняются.

### 7. Обновление

```bash
git pull
docker compose up --build -d
```

Тома с базой, индексом и моделями сохраняются.

### Остановка и удаление данных

Остановить контейнеры, данные оставить:

```bash
docker compose down
```

Удалить тома SQLite, ChromaDB и моделей Ollama:

```bash
docker compose down -v
```

Чужие контейнеры на сервере эта команда не трогает. Пароли в `.env` файл не удаляет.

## Возможности

В шапке три раздела: список тредов, сводка, настройки.

### Список тредов

Письма сгруппированы в переписки по теме и заголовкам `Message-ID`, `In-Reply-To` и `References`. Карточка показывает тему, участников, число писем, время и превью последнего письма. Список отсортирован по дате последней активности.

Поиск идёт по теме и участникам, не по полному тексту писем. На экране первая страница, до 25 тредов.

Кнопка «Синхронизировать» забирает входящие за выбранный срок. Пустой список значит, что синхронизация ещё не запускалась или за период писем нет.

За один запуск читается папка **INBOX** и не больше **5000** писем за окно `SYNC_DAYS` (по умолчанию 30 дней). Другие папки, отправленные и корзина не читаются. Ящик не помечается прочитанным и не изменяется.

### Тред

Слева хронология: отправитель, время, текст. У вложений видны только имена файлов, содержимое не разбирается.

Справа три вкладки.

**Саммари.** Кнопка «Обновить саммари» просит модель кратко пересказать переписку: тема, договорённости, открытые вопросы. Если после саммари в тред попали новые письма, интерфейс помечает текст устаревшим.

**Вопрос.** Свой вопрос по этой переписке. Ответ строится по письмам треда: релевантные фрагменты ищутся в локальном индексе. Если индекс пуст или недоступен, в модель уходит текст треда целиком. Слишком длинный контекст отклоняется, данные при этом не пропадают.

**Черновик.** Тон: деловой, нейтральный или дружелюбный. «Составить черновик» готовит ответ на русском по последним письмам треда, без выдуманных фактов. «Скопировать в почту» кладёт текст в буфер обмена. Отправки нет.

Пока идёт одна генерация, вторая получит сообщение подождать: Ollama обрабатывает один запрос за раз. Саммари и черновики старше 90 дней удаляются при старте приложения. Сами письма лежат в базе, пока вы не смените ящик и не удалите тома.

### Утренняя сводка

Три блока за последние `DIGEST_HOURS` (по умолчанию 24 часа):

- срочные письма — со ссылкой в тред;
- задачи — чекбокс отмечает задачу выполненной, выполненное не сбрасывается при следующем пересчёте;
- ожидаемые ответы — со ссылкой в тред.

«Обновить сводку» пересчитывает список моделью сразу. Отдельно сводка строится сама каждый день в `DIGEST_HOUR` (по умолчанию 08:00 по часам контейнера). Это не синхронизация почты: в сводку попадают только уже загруженные письма. Если утром ящик ещё не синхронизировали, сводка будет по старым данным.

Тексты модели — подсказка. Перед решением и перед отправкой письма их нужно прочитать.

### Настройки

- Почта: тестовый ящик или живой IMAP, сервер, порт, SSL, логин, пароль.
- Модель: `qwen2.5:7b-instruct` и индикатор, отвечает ли Ollama.
- Синхронизация: за сколько дней забирать входящие и за сколько часов строить сводку.

Пароль, введённый в форме, хранится в SQLite в зашифрованном виде. В лог он не пишется. Если поле оставить пустым, используется уже сохранённый пароль или `IMAP_PASSWORD` из `.env`.

### Тестовый ящик

Режим «Тестовый ящик» (`IMAP_MODE=mock`) не ходит в интернет за почтой. Письма читаются из каталога `fixtures/emails`. Так проверяют интерфейс и автотесты без настоящего аккаунта. «Проверить подключение» в этом режиме подтверждает, что фикстуры на месте, а не логин на IMAP-сервере.

### Чего продукт не делает

- Не отправляет письма и не подключается по SMTP.
- Не входит через OAuth, Google, Microsoft или Apple ID.
- Не читает Exchange и CommuniGate, если у них нет обычного IMAP.
- Не открывает папки кроме INBOX и ничего не записывает в ящик.
- Не вытаскивает текст из вложений.
- Не опрашивает почту в фоне.
- Не рассчитан на несколько пользователей, роли и журнал аудита.
- Не вызывает внешние языковые API: и ответы, и эмбеддинги считает локальная Ollama.

## Подключение Gmail и других ящиков

Клиент универсальный: в настройках задаются сервер, порт, SSL, логин и пароль. Отдельных коннекторов под провайдеров нет. OAuth не используется.

Общий порядок:

1. У провайдера включите доступ по IMAP.
2. Если включена двухфакторная защита, создайте **пароль приложения**. Обычный пароль от аккаунта и вход «через Google / Microsoft / Apple» здесь не подходят.
3. В INGOSight: режим «IMAP», сервер и порт из таблицы, галочка SSL, логин (как правило полный адрес почты), пароль приложения.
4. «Сохранить» → «Проверить подключение» → «Синхронизировать».

Пробелы в пароле приложения можно не убирать: перед входом они отбрасываются.

Ниже стандартные адреса IMAP. Провайдер может изменить их или отключить доступ; если проверка не проходит, сверьтесь с его справкой.

| Сервис | Сервер | Порт | SSL | Пароль |
| --- | --- | --- | --- | --- |
| Gmail | `imap.gmail.com` | 993 | да | Пароль приложения Google, 16 букв |
| Google Workspace | `imap.gmail.com` | 993 | да | То же, если администратор домена разрешил IMAP |
| Яндекс | `imap.yandex.ru` | 993 | да | Пароль приложения, если включена двухфакторная защита |
| Mail.ru | `imap.mail.ru` | 993 | да | Пароль для внешнего приложения, если обычный пароль не принимают |
| Outlook, Hotmail, Microsoft 365 | `outlook.office365.com` | 993 | да | Пароль приложения. Если организация отключила вход по паролю IMAP, ящик не подключится |
| Yahoo | `imap.mail.yahoo.com` | 993 | да | Пароль приложения Yahoo |
| iCloud | `imap.mail.me.com` | 993 | да | Пароль приложения Apple ID |
| Rambler | `imap.rambler.ru` | 993 | да | Пароль ящика или пароль приложения, если он включён |

### Gmail

1. В Gmail: «Настройки» → «Все настройки» → «Пересылка и POP/IMAP» → включите IMAP → «Сохранить изменения».
2. В аккаунте Google: «Безопасность» → двухэтапная аутентификация должна быть включена → «Пароли приложений». Создайте пароль для почты.
3. Вставьте эти 16 букв в поле «Пароль» в INGOSight (или в `IMAP_PASSWORD`). Логин — полный адрес `@gmail.com`. Сервер `imap.gmail.com`, порт `993`, SSL включён.
4. Режим «IMAP», затем «Проверить подключение» и «Синхронизировать».

Для Google Workspace IMAP должен быть разрешён администратором домена. Иначе проверка подключения завершится ошибкой, даже с верным паролем приложения.

### Яндекс

В почте Яндекса включите доступ по IMAP (раздел почтовых программ). При двухфакторной защите создайте пароль приложения в настройках аккаунта Яндекса и укажите его вместо основного пароля. Сервер `imap.yandex.ru`, порт `993`, SSL, логин — полный адрес.

### Mail.ru

В настройках почты Mail.ru откройте «Почтовые программы» и разрешите доступ по IMAP. Если аккаунт не принимает основной пароль из внешнего клиента, создайте пароль для внешнего приложения в настройках безопасности. Сервер `imap.mail.ru`, порт `993`, SSL, логин — полный адрес.

### Outlook, Hotmail и Microsoft 365

Сервер `outlook.office365.com`, порт `993`, SSL, логин — полный адрес. При двухфакторной защите в безопасности аккаунта Microsoft создайте пароль приложения.

Многие корпоративные тенанты Microsoft 365 отключают вход по паролю и оставляют только OAuth или Exchange. Такой ящик эта версия не подключит: отдельного входа Microsoft в приложении нет.

### Yahoo

В безопасности аккаунта Yahoo создайте пароль приложения (для IMAP он обычно обязателен). Сервер `imap.mail.yahoo.com`, порт `993`, SSL, логин — полный адрес Yahoo.

### iCloud

В Apple ID откройте «Вход и безопасность» и создайте пароль приложения. Сервер `imap.mail.me.com`, порт `993`, SSL. Логин — адрес Apple ID, которым вы входите в почту iCloud.

### Rambler

Включите IMAP в настройках почты Rambler. Сервер `imap.rambler.ru`, порт `993`, SSL, логин — полный адрес `@rambler.ru` (или другой домен Rambler, если ящик на нём).

### Другой IMAP-сервер

Те же поля: хост, порт, SSL, логин, пароль. Логин чаще всего совпадает с полным адресом почты. Для шифрованного IMAP обычно порт 993 и включённый SSL. Порт без SSL возможен, но для почты с паролем его лучше не использовать.

Не подойдут ящики, у которых нет IMAP: Exchange и CommuniGate без IMAP-доступа, а также вход только через OAuth. Запись в ящик и папки кроме «Входящие» не поддерживаются.
